# U04 — 保存、恢复与 UI/API 导出

**状态：未运行。前置：U01、U02、U03。** 目标：证明编辑信息可恢复，理解用于编辑的工作流文件与用于执行的请求并不相同。

## 准备与控制变量

使用 U03 的可运行工作流，包含至少一个重路由、一个 Note 和两个普通分组。将 Note 设为唯一标记 `U04-check-001`，两组分别命名为“输入区”和“预览区”。截下全图，记录各节点位置、连线、图片输入名称与输出。先保存云端副本，防止导入覆盖当前内容。

## 单变量用例与可观察预期

| 用例 | 操作与变量 | 明确预期 | 观察/通过标准 |
|---|---|---|---|
| U04-01 云端重开 | 明确保存并等待完成，再退出当前工作流并从工作区重新打开同一条目 | Note 标记、分组标题/颜色/范围、节点位置、重路由和连线恢复 | 对照保存前截图逐项检查。画布缩放/视角和临时预览是否保留单独记录，不作为图结构恢复的必要条件 |
| U04-02 UI 导出回读 | 若提供普通工作流/UI JSON 导出，导出后在新建副本导入 | 支持的 UI 格式应恢复节点、注释、分组和等价连线；重新运行仍输出同图 | 逐项对照；输入资源若未随 JSON 打包，重新上传同一 PNG 再运行，并记录该依赖；不能因缺图片误判注释丢失 |
| U04-03 API 对照 | 若提供 API 格式导出，对同一工作流导出并与 UI 文件比较；不调用远端 API | API 执行描述应保留实际计算节点和上游数据来源；Note/分组通常不作为独立后端执行节点，重路由通常被消解为上游连接 | 查找 LoadImage、PreviewImage 及其输入来源；记录是否有额外 UI 元数据。导出器若包装了 workflow 元数据，应将其与执行描述区分，不要求整个文件搜不到 Note |
| U04-04 恢复检查 | 在副本中修改 Note 标记及组名而保持图像路径不变；随后通过重新导入 U04-02 保存文件恢复 | 导入保存版本后标记恢复为 U04-check-001，组名恢复，连线等价；同图输入仍产生同图输出 | 保留修改后和恢复后截图。仅有 API 文件时不宣称可以完整恢复布局；若无 UI 导出入口，此项标不可用 |

不要求导出再导入前后 JSON 字节、节点编号或键顺序完全一致；验收对象是记录的内容、布局与数据路径。若所用新版重路由不能被当前导入器保留，要记为兼容性问题，不能仅因为输出相同就宣布 UI 回读完整通过。

## 结果分类与排查

- 云端保存失败：记录提示和条目链接，不能仅凭画布仍显示内容就认定保存成功。
- 图像资源失效：核对是否导入了相同图片，分别记录“图结构恢复”和“资源可用”。
- API 文件缺少分组：先检查它是否只为执行服务；布局不在此格式中不是普通 UI 保存失败。
- RunningHub 没有某种导出入口：标“当前环境不可用”，不承诺所有账号支持所有格式。

## 通关与证据

保存 UI 工作流文件（若可导出）、可选 API 文件、四行用例记录以及保存前/恢复后截图。文件放入个人记录目录，参照 [工作流保存说明](../../workflows/README.md) 标注版本、格式与素材依赖。分享前移除账号令牌、私有访问链接等信息。

通关标准：可以恢复并运行同一条数据路径，准确指出哪些证据证明画布恢复、哪些证明执行结果一致；能说明为什么 API 导出不能默认当成完整编辑备份。
