## 准备与接线

保留基准副本。将 LoadImage 的 IMAGE 输出与 PreviewImage 之间的连接改为 `LoadImage → Reroute → PreviewImage`。若使用原生重路由点，沿该连线添加一个点，并记录具体入口。暂不改变图片、输出节点参数或节点执行模式。

## 单变量用例与可观察预期

每行独立执行，开始前恢复本行指定的基线。精确像素判定使用目录中的 SaveImage 对照方法。

| 用例 | 操作与变量 | 明确预期 | 观察/通过标准 |
|---|---|---|---|
| U01-01 插入 | 从直连开始，增加一个重路由节点或点，保持原端口对应 | 线分成经过重路由的路径；图片宽高、颜色、内容不变 | 当前任务成功；记录前后接线截图；像素对照应 equal=true |
| U01-02 位置 | 在 U01-01 连接基础上，先移到上方，再移到下方 | 连线形状随位置变化；数据来源与去向不变，图片不变 | 两个位置各截图；两次输出均与基准像素相同 |
| U01-03 分支 | 增加第二个 PreviewImage，让同一上游经重路由向两个预览供图 | 两个下游都收到同一图片；不是把图切成两半，也不是生成新图 | 两个预览宽高和内容一致；精确验证时为两支各接一个 SaveImage 并比较像素 |
| U01-04 断路与修复 | 只保留一个预览支路，在副本中断开其必需 images 数据路径，提交；再恢复连接提交 | 断路时不能产生该预览的新有效结果，通常出现缺少输入/连接无效提示；恢复后成功显示原图 | 记录当前任务错误，不能以旧预览仍存在判成功；修复后记录成功任务。具体错误文字不作硬性要求 |
| U01-05 数量 | 将路径中重路由数量依次设为 0、1、3，保持端口对应和同一输入 | 布线结构变化，三种配置的图像结果相同；不因多放重路由而提高分辨率或质量 | 三种连接截图及同基准像素对照；不以耗时差别判断通过 |

若原生重路由点的分支入口不同，先使用界面实际支持的方法；无法创建时将 U01-03 标“当前环境不可用”，不要用其他数据处理节点替代。

## 常见偏差与排查

- 没有输出：沿线检查 IMAGE → images 是否完整，查看当前任务状态。
- 插入后图像变化：检查是否误接 MASK、是否更换输入或添加处理节点；重路由本身不应修改像素。
- 传统节点与原生点导出的 JSON 不同：分别记录实现；本组以数据路径和输出等价为标准，不要求 JSON 相同。
