## RunningHub 环境核对

1. 进入可编辑的 **ComfyUI 工作流画布**。只有上传素材、填写参数的 AI 应用表单不能完成本实验；也不要将平台的其他“无限画布”产品视作同一个编辑器。
2. 记录日期、工作流链接和编辑器版本（界面未展示则记“未知”）。记录右键菜单/搜索菜单中实际出现的名称，并截图；不要假定快捷键与本地最新版相同。
3. 查找 Note、Reroute 和创建分组的入口。Group 可能是画布菜单操作，未必能在节点搜索中找到。传统 Reroute 节点与新版原生重路由点应分开记录；若两者都有，先选一种完成实验，再用另一种复做。
4. 某入口缺失时记“当前环境不可用/待确认”，保留菜单截图，不据此判定整个 ComfyUI 不支持。不要用第三方同名节点替代后仍声称测试了内置功能。

公开 RunningHub 工作流的节点清单包含 Note、Reroute，说明平台存在使用它们的工作流；这不等于本项目已验证所有账号和编辑器版本的操作。Group 的具体菜单和移动手势仍需现场确认。

## 基准准备（无需生成模型）

1. 准备一张不透明的 RGB PNG，建议 512×384，含红、绿、蓝色块及明显方向标记。始终使用同一文件，不裁剪、不缩放、不更换图片。
2. 新建工作流，添加 LoadImage 和 PreviewImage。连接 LoadImage 的 **IMAGE** 输出到 PreviewImage 的 images 输入，勿误接 MASK。
3. 运行一次，确认任务成功且预览显示原图；记录预览宽高、颜色与方向。命名为 `U00-baseline` 并保存副本。
4. 若要精确判定像素，在同一 IMAGE 输出增加 SaveImage，保存基准 PNG 为 `baseline.png`。之后保持这个输出路径，只改变待测前端操作；下载对应新任务的 PNG 为 `variant.png`。
5. 每个用例先填写预测，再操作、截图、填写实测。破坏性连线实验在副本中执行，完成后恢复基准连接。

精确对照可在本机安装 Pillow、NumPy 后，使用项目的测量工具：

```bash
python3 tools/measure.py image variant.png --reference baseline.png
```

预期 `equal=true`、`mae=0`、`max_abs_error=0`，宽高相同。比较的是两次输出的解码像素，不是 PNG 文件哈希；保存的工作流元数据可能导致文件字节不同。截图只能证明界面现象，不能证明逐像素相等。

## 观察规则与结果状态

- 纯文字编辑、拖动和分组无需执行模型；输出对照只需读图、预览/保存。此处不对平台计费作承诺。
- 修改前端布局后重新提交可能命中缓存，这是正常现象；不要求任务耗时变化，也不要求后端重新计算才算通过。
- 出现报错时可能仍显示上次的预览。必须结合当前任务状态判断，不能把旧图当成新运行成功。
- 每个用例记“未运行 / 通过 / 失败 / 当前环境不可用 / 待确认”，附截图或工作流证据。版本不同导致入口变化，先记录差异再分析。
- 每次只改变表格所列变量。不能同时更换输入图片、改变图像节点参数或切换节点执行模式。
